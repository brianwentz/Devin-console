# Devin Workspaces — project rules

Electron desktop client for Devin (BaseWindow + WebContentsViews; the React shell is the only view exposing a window API via preload).

## Commands
- `npm run typecheck` — `tsc --noEmit`
- `npm run test:unit` — vitest, `tests/unit` (pure logic only)
- `npm run build` — esbuild (main/preload/scripts → `out/*.cjs`) + `vite build` (shell → `out/shell`); runs a dependency preflight first (`src/core/depPreflight.ts` → `out/scripts/dep-preflight.cjs`) and exits 1 with a `run npm install` message when a package.json dependency is missing from node_modules
- `npm run test:e2e` — build + Playwright `_electron` (`tests/e2e`, fixture servers in `tests/fixtures/http.ts`)
- `npm run dist:win` — build + electron-builder NSIS per-user x64 installer → `dist/DevinWorkspaces-Setup-<version>.exe` (unsigned, fuses flipped by electron-builder from `build.electronFuses`; `scripts/after-pack.cjs` only writes `resources/signing.json`; icon from `build/icon.ico` via `npm run icon`)
- `npm run dist:mac` — build + electron-builder arm64 dmg+zip → `dist/DevinWorkspaces-<version>-arm64.*` + `latest-mac.yml`; ad-hoc signed (`-c.mac.identity=- -c.mac.hardenedRuntime=false` — hardened runtime off because ad-hoc signatures have no team ID), so Gatekeeper requires right-click → Open on first launch (icon from `build/icon.png`, entitlements `build/entitlements.mac.plist`). Never reintroduce fuse-flipping in afterPack — it invalidates the Electron ad-hoc signature → "application is damaged".
- `npm run smoke:install` — `npm run dist:win:smoke` (same build packaged as "Devin Workspaces Smoke", appId `ai.devin.workspaces.smoke`, `dist/smoke/DevinWorkspaces-Smoke-Setup-*.exe`) then `scripts/smoke-install.ps1 -Isolated`: silent install → `tests/smoke/installed.spec.ts` (CDP-driven, `playwright.smoke.config.ts`) → upgrade-in-place → uninstall; evidence in `docs/evidence/p3-smoke*` (docs/ is git-ignored - local output only). Run before pushing when packaging or the settings schema changes (it reads `settings.json` directly). The isolated identity exists because electron-builder's NSIS always uninstalls the registered install of the same appId (`HKCU\Software\<GUID>\InstallLocation`, regardless of `/D=`) — smoking the real artifact on a dev machine removes the user's installed app. `npm run smoke:install:real` smokes `dist/DevinWorkspaces-Setup-*.exe` and is CI-only (`windows.yml`); the script refuses to run when a non-smoke install of the product is registered or running (`-Force` bypasses; never set from package.json), and only ever kills processes under its own `-InstallDir`. The smoke spec reaches main-process test hooks through the test-mode-only `test:hook` IPC (`devinworkspaces.testHook(name, ...args)`, registered in `registerTestHooks`) because Electron's browser CDP target does not implement `Runtime.evaluate`.
- `npm start` / `npm run acp:probe`
- `npm run claude:sdk-probe` / `claude:hooks-probe` / `claude:store-probe` — build then run `scripts/claude-*-probe.ts` → `out/scripts/*.cjs`; evidence under `docs/evidence/claude-*` (git-ignored); exit 0 when the claude CLI is missing (reported in the file)
- CI: `.github/workflows/windows.yml` (push/PR: typecheck, unit, build, e2e, dist:win, smoke:install, plus a `macos` job running typecheck/unit/build/dist:mac only — e2e and smoke stay Windows-only); `release.yml` (on `release: published` with tag `vX.Y.Z` created in the GitHub UI: sets package.json to X.Y.Z, builds Windows + macOS arm64, uploads `.exe`/`.blockmap`/`.dmg`/`.zip`/`latest.yml`/`latest-mac.yml` to that release — the feed used by `src/main/updater.ts` — then commits `chore: release vX.Y.Z` to main; never bump the version by hand; mark a release as pre-release to keep clients from auto-updating to it; macOS signing/notarization is optional via secrets `CSC_LINK`, `CSC_KEY_PASSWORD`, `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD`, `APPLE_TEAM_ID` — unsigned Mac builds have the updater disabled: `updater-disabled reason: unsigned-mac`, gated by `resources/signing.json` written by after-pack)

Smoke only: `DEVIN_WORKSPACES_INSTALLED_EXE`, `DEVIN_WORKSPACES_SMOKE_PROFILE`, `DEVIN_WORKSPACES_SMOKE_PHASE` (`fresh`|`upgrade`), `DEVIN_WORKSPACES_SMOKE_EVIDENCE`. `DEVIN_WORKSPACES_TEST=1` also disables the auto-updater. `DEVIN_WORKSPACES_EVIDENCE=1` makes the routing e2e write its event log to `docs/evidence/e2e-fixture-events.jsonl` (default: temp profile; docs/ is git-ignored).

- `npm run acp:contract` — P4 contract run against the real `devin acp` (initialize/new/prompt/cancel/list/load); writes `docs/evidence/p4-acp-contract.jsonl` (git-ignored); exit 0 also when the CLI is missing/unauthenticated (reported in the file)
`DEVIN_WORKSPACES_TEST_AUTH_STATUS_CMD` (test mode only, e.g. `node out/fixtures/fakeAuthStatus.cjs`) replaces the `devin auth status` spawn used for service-user identity resolution; the fake reads `FAKE_AUTH_STATUS_EXIT` / `FAKE_AUTH_STATUS_USER_ID` / `FAKE_AUTH_STATUS_ORG_ID`.
`DEVIN_WORKSPACES_LOCAL_AGENT_CMD` (test mode only, e.g. `node out/fixtures/fakeAcpAgent.cjs`) replaces the `devin acp` spawn with a full command; the fake agent reads `FAKE_ACP_LIST=1` / `FAKE_ACP_LOAD=1` / `FAKE_ACP_DELETE=1` / `FAKE_ACP_LINK_URL` / `FAKE_ACP_USAGE=1` (emits a `usage_update` mid-prompt and `usage` on the prompt response) / `FAKE_ACP_PROMPT_DELAY_MS` (stalls the prompt so the thinking indicator is observable). `DEVIN_CLI` overrides the binary for `acp:probe` / `acp:contract`.
`DEVIN_WORKSPACES_TEST_TERMINAL_CMD` (test mode only, e.g. `node out/fixtures/fakePty.cjs`) replaces the command the embedded terminal spawns — for both `devin`-kind (Local panel) and `shell`-kind (dock) ptys.
`DEVIN_WORKSPACES_TEST_CLOUD_SESSIONS` (test mode only, path to a JSON file shaped like `CloudListResult` — `{ sessions: CloudSession[], folders: string[], folderTotals: {}, nextCursor }`) makes the cloud sidebar data layer (`src/main/cloudSessions.ts`) skip the network and load the file at start and on every `cloudRefresh()`; unset in test mode → `cloud.status` is `'disabled'`. Test hooks: `cloudState()`, `cloudRefresh()`, `setSessionsOpen(v)`, `getSessionsBounds()`. `DEVIN_WORKSPACES_TEST_CLOUD_CACHE` (test mode only, path to a JSON file in `CloudCache` shape — `{version:1, tenantUrl, savedAt, sessions, folders, folderTotals}`) loads that file as the cached list when no fixture file is set, leaving `cloud.status` `'connecting'` with `cached: true`.
`DEVIN_WORKSPACES_TEST_SESSIONS_OPEN` (test mode only, `'1'`/`'0'`) overrides `settings.sessions.open` at startup; `launchApp` sets `'0'` by default so legacy specs keep `devin.x === RAIL_WIDTH` — sidebar specs pass `'1'`.
`DEVIN_WORKSPACES_TEST_CLOUD_KEEPALIVE_MS` (test mode only) overrides `settings.sessions.keepAliveHours` for the pooled Cloud views — mirrors `DEVIN_WORKSPACES_TEST_KEEPALIVE_MS` (tabs). Test hooks: `cloudViewsInfo()`, `cloudShow(id)`, `cloudPrefetchHook(id)`, `cloudIdleSweep()`, `setCloudKeepAliveMs(ms)`; `ipcProbe()` also reports `pooled` (whether a non-active pooled view passes `fromHostedView`).

## Versions
Requires Node ≥ 22.12; currently developed on Node 24.x. All deps are pinned exact — package.json is the source of truth. Couplings: `@types/node` must stay on the Node major bundled by the current Electron (Electron 44 → Node 24), not `latest`; `electron-builder` tracks the `v26` npm dist-tag (its `latest` tag lags behind). Dependabot (`.github/dependabot.yml`) opens weekly PRs with a 7-day cooldown; CI runs `npm audit --audit-level=high` after `npm ci`. `@anthropic-ai/claude-agent-sdk@0.3.296` is pinned — its `manifest.json` targets Claude CLI 2.1.296, so check `claude --version` against it when bumping; the `@anthropic-ai/claude-agent-sdk-<platform>` optional deps are install-only (they bundle claude.exe) and must never ship in the installer. The SDK is ESM-only, so it stays `external` in `scripts/build.mjs` and is packaged unpacked: `build.files`/`build.asarUnpack` carry it plus its runtime deps (ajv, ajv-formats, fast-deep-equal, fast-uri, json-schema-traverse, require-from-string, zod) with `!`-negations excluding the platform packages, `@anthropic-ai/sdk` and `@modelcontextprotocol/*`; `scripts/smoke-install.ps1` fails the installer over a 260 MB size budget.

## Conventions
- `src/core/` is pure TS — no `electron` imports (unit-testable).
- All IPC payloads are validated with the zod schemas in `src/shared/ipc.ts`; add a schema when adding a channel.
- IPC handlers go through `ipcGuard` (`guardedHandle`/`guardedOn`) — shell sender only.
- Log URLs/ids/lengths only — never page or process output text (terminal output, ACP stderr, credential usernames/passwords are all excluded).
- `tenantUrl`/`apiBase` must be https (localhost http only in tests via `DEVIN_WORKSPACES_TENANT_URL`).
- Remote views (devin + `gh:*` tabs) get only `out/autofill-preload.cjs` (`src/autofill/preload.ts`): sandbox + contextIsolation stay on, it exposes nothing via contextBridge, and it talks to main only over `autofill:*` channels guarded by `hostedHandle`/`hostedOn` (`fromHostedView`: sender is a hosted view, frame origin == top-frame origin). Partitions stay separate.
- Shell loads only `app://shell/...`; strict CSP — `script-src 'self'`, no inline script; `style-src` allows `'unsafe-inline'` only because xterm.js injects `<style>` elements (P4b) — keep all other directives unchanged.
- Explicit `webContents.close()` on tab/window teardown; the splitter drag live-resizes hosted views (`moveDrag` → `applyBounds` + a non-persisting `state:update`) — never restack the shell mid-drag, and on macOS `raiseShell` paints the shell opaque because a transparent top view does not composite (white-out).
- Secrets (vault passwords) never reach renderers or logs; credential IPC handlers must not log payloads.
- Passwords (autofill): `credentials.json` v2 is id-keyed with many accounts per origin (v1 migrates on load) in `src/main/credentials.ts`; login-form heuristics live in `src/core/autofillModel.ts`; main side is `src/main/autofill.ts`; shell overlays `AccountPicker.tsx` / `SavePasswordBanner.tsx` are raised via `overlayOpen()` in `window.ts`. One account → fill on load (never submits); several → account picker on field focus; a submitted login → save/update prompt after the next navigation or 1.5 s, auto-dismissed after 10 s. Log events: `autofill-query`, `autofill-picker`, `autofill-capture`, `autofill-prompt`, `autofill-save`, `autofill-save-failed`, `autofill-dismiss`, `credential-add|update|delete|reveal` — origins/counts only. Removed channels: `credentials:fill`, `credentials:menu`.
- Cloud view pool: `state.devinView` is a getter for `cloudViews().activeView()` (`src/main/cloudViews.ts`) — views are keyed by the session they display (`keyForUrl`, `'home'` for tenant root); switching just reattaches. Only the active pooled view is laid out/attached; `rekey` follows in-app navigations (background view navigating onto another pooled session destroys the duplicate). Discard honours beforeunload (same 3 s/50 ms race as TabManager; cancelled → `protected`). Log events `cloud-view-show|create|rekey|duplicate|discard|discard-cancelled|crashed` — kinds/counts/ids only.
- Passwords (autofill): `credentials.json` v2 is id-keyed with many accounts per origin (v1 migrates on load) in `src/main/credentials.ts`; login-form heuristics live in `src/core/autofillModel.ts`; main side is `src/main/autofill.ts`; shell overlays `AccountPicker.tsx` / `SavePasswordBanner.tsx` are raised via `overlayOpen()` in `window.ts`. One account → fill on load (never submits); several → account picker on field focus; a submitted login → save/update prompt after the next navigation or 1.5 s, auto-dismissed after 10 s. Log events: `autofill-query`, `autofill-picker`, `autofill-capture`, `autofill-prompt`, `autofill-save`, `autofill-save-failed`, `autofill-dismiss`, `credential-add|update|delete|reveal` — origins/counts only. The Settings Passwords tab lists accounts in `#credentialsTable` rows `tr[data-credential-id]` (sorted by origin then username; empty state `#credentialsEmpty`). Removed channels: `credentials:fill`, `credentials:menu`.
- The Devin API token lives only in `src/main/secrets.ts` (safeStorage-encrypted `userData/secrets.json`) and main-process memory: never add it to `ShellState`, IPC replies, or `log()` calls. Scrub error strings with `sanitizeMessage`.
- `tabs-preload` event: on scope switch/launch the visible scope's discarded tabs are background-loaded (150 ms stagger); the live cap (`tabs.maxLiveTabs`) and idle discard apply to hidden scopes only — the visible scope's tabs are exempt.
- P6 notification center: `src/core/notificationModel.ts` (derive/list ops, pure) + `src/main/notifications.ts` (persisted store in `notifications.json`; 'update' entries are runtime-only). IPC: `notifications:list|markRead|markAllRead|remove|clear|open|panel|identity|identityReset`, push `notifications:banner`. While the panel is open main raises the shell view (`setNotificationsPanel`/`raiseShell`); the raise must survive `applyLayout` and surface switches close it. Taskbar overlay = unread count (`badge` log event); no OS toasts. The badge PNG is drawn on an offscreen canvas in the shell (`src/shell/badge.ts`, spec from `src/core/badge.ts` — Slack red `#e01e5a`, 16 px × display scale): main sends `badge:render {count,size}`, the shell replies over `badge:rendered {dataUrl}` whose handler returns the desired `{count,size}` so a late-mounting shell converges (nativeImage cannot rasterise SVG). Entries carry `ownerUserId`; `NotificationStore.reconcile(userId)` runs once per `/v3/self` resolution and prunes session-scoped entries from other users / legacy builds (`notifications-pruned` log event, counts only); the `identity` kind is runtime-only like `update` and is raised once for service-user tokens.
- App version + update status: `ShellState.update` = `{ version (app.getVersion()), available, downloaded, releasesUrl, enabled, checking, lastCheckedAt, error }` from `src/main/updater.ts`; the Settings Updates tab renders `#aboutSection` (`#appVersion`, `#updateStatus[data-update-state=none|downloading|ready]`, `#updateNow`, `#updateCheckNow` / `#updateLastChecked` / `#updateError` while not downloaded), `#releasesLink` (opens via `link:open`), and release-notes cards `#releaseNotesAvailable` / `#releaseNotesCurrent` (`data-notes-state=loading|ok|missing|error`). `update:install` (shell-only, no payload) calls `installUpdate()` only when a download is ready. `update:check` (guardedOn, `UpdateCheckArg { source: 'settings' | 'manual' }`) calls `checkForUpdatesNow` — the tab auto-checks on mount ('settings') and `#updateCheckNow` sends 'manual'. Checks also run on `powerMonitor` resume/unlock-screen and window focus; timer interval is 2 h.
